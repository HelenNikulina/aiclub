# Гайд: Память Claude Code между сессиями (для claude.ai/code)

Этот гайд — для тех, кто работает с Claude Code через браузер или десктоп-приложение (`claude.ai/code`). Если ты пользуешься **локальным Claude Code CLI** в терминале — подход другой, смотри раздел «Локальный CLI» в конце.

---

## Что получим

- Claude **знает тебя и твои проекты** в каждом новом чате
- Не надо каждый раз объяснять «я Python-разработчик», «использую FastAPI», «мой бот в ветке X»
- Claude **сам записывает** важные решения и факты по ходу работы — чтобы не забыть после падения сессии

---

## Почему НЕ работает «стандартный» подход

Тебе могли посоветовать настроить `~/.claude/CLAUDE.md`, `~/.claude/MEMORY.md` или хуки в `~/.claude/settings.json`. **Для `claude.ai/code` это бессмысленно.** Почему:

- Каждый новый чат запускается в **новом облачном сендбоксе** (временный контейнер).
- В сендбоксе **пустая домашняя папка** `~/.claude/`. Всё, что ты туда записала в предыдущем чате, исчезло.
- Хуки в `settings.json` не успевают сработать даже раз — файла не существует в новом чате.

То, что **переживает** новый сендбокс, — это **твой GitHub-репозиторий**, потому что он клонируется с GitHub при старте каждого чата. Вывод: **память должна лежать в репо**, а не в домашней папке.

---

## Рабочий подход — два файла в репо

| Файл | Путь | Что содержит | Кто пишет |
|---|---|---|---|
| `CLAUDE.md` | корень репо | Постоянный контекст: кто ты, правила, инфраструктура | Ты + Claude по запросу |
| `MEMORY.md` | корень репо | Саммари сессий: решения, изменения, незавершённое | Claude — автоматически, проактивно |

Оба файла коммитятся в ветку **`main`**. Каждый новый чат клонирует `main` → видит эти файлы → знает тебя.

---

## Пошагово

### Шаг 1. Открой свой рабочий репо в Claude Code

Зайди на `https://claude.ai/code`, открой новый чат на том репо, с которым ты регулярно работаешь. Если такого нет — создай в GitHub новый репо (например, `my-claude-memory`) и открой его.

### Шаг 2. Убедись, что default branch — `main`

Это критично. Если default другой — новый чат клонирует его и память не увидит.

1. Открой `https://github.com/<юзернейм>/<репо>/settings`
2. Слева: `General` → прокрути вниз
3. Найди блок **Default branch**
4. Если там не `main` — нажми ⇄ → выбери `main` → **Update** → подтверди

### Шаг 3. Попроси Claude создать `CLAUDE.md`

Скопируй этот запрос в чат:

> Создай в корне репо файл `CLAUDE.md` для постоянного контекста. Структура:
> - Заголовок «Контекст для Claude — прочитай перед любым действием»
> - Раздел «Память сессий»: «также сразу прочитай `MEMORY.md` в корне репо»
> - Раздел «Кто я» (пустой, я заполню)
> - Раздел «Правила работы со мной» (пустой)
> - Раздел «Мои проекты» (пустой)
>
> Закоммить в ветку `main` и запушь через `git push origin main`.

### Шаг 4. Попроси Claude создать `MEMORY.md`

> Создай в корне репо файл `MEMORY.md` с заголовком «Память — саммари сессий» и коротким описанием формата: новые секции в конец файла, заголовок вида `## YYYY-MM-DD HH:MM — краткое описание`, 3-7 буллетов. Закоммить в `main`, запушь.

### Шаг 5. Заполни `CLAUDE.md` своим контекстом

Просто расскажи Claude о себе. Пример:

> Запиши в `CLAUDE.md` (разделы «Кто я» и «Правила»):
> - Я Python-разработчик начального уровня, нужны подробные объяснения с примерами
> - Всегда отвечай по-русски
> - Мой основной проект — телеграм-бот, ветка `bot-main`
> - Сервер на Hostinger VPS, доступ через Browser terminal
>
> Закоммить в `main`, запушь.

### Шаг 6. Добавь правило проактивности в `CLAUDE.md`

Без этого Claude будет писать в `MEMORY.md` только когда ты попросишь. С ним — сам.

> Допиши в `CLAUDE.md` раздел «Как обновлять MEMORY.md»:
>
> Не ждать команды «обнови память» и не ждать конца сессии. Записывать сразу при:
> - принятом техническом решении
> - значимом коммите/пуше
> - выявленном факте/ограничении, которое понадобится дальше
> - незавершённой задаче, которую надо передать следующей сессии
>
> Каждое обновление `MEMORY.md` делать **только в ветке `main`**:
> ```
> current=$(git branch --show-current)
> git checkout main && git pull origin main
> # Edit MEMORY.md (новая секция в конец)
> git add MEMORY.md && git commit -m "memory: <описание>" && git push origin main
> git checkout "$current"
> ```
>
> Закоммить это дополнение в `main`, запушь.

### Шаг 7. Проверь в новом чате

1. Закрой текущий чат
2. Открой тот же репо в **новом** чате на `claude.ai/code`
3. Спроси: **«Что ты обо мне знаешь?»**
4. Должен сразу пересказать всё из `CLAUDE.md` и `MEMORY.md`

Если пересказывает — всё работает. Если «ничего не помню» — см. таблицу ниже.

---

## Что НЕ писать в эти файлы

`CLAUDE.md` и `MEMORY.md` лежат в git → видны всем, у кого есть доступ к репо. Если репо публичный — вообще всем в интернете.

**Запрещено:**

- API-ключи, токены, пароли (даже тестовые — это привычка)
- Личные данные третьих людей
- Production-секреты — им место в `.env` + `.gitignore`

Для приватного репо тестовые токены технически можно, но привычка держать всё в `.env` надёжнее.

---

## Как чистить, когда `MEMORY.md` разрастётся

Раз в месяц:

> Открой `MEMORY.md` на ветке `main`, убери секции старше месяца (кроме незавершённых задач и важных решений). Закоммить, запушь в `main`.

---

## Что чинить, если не работает

| Симптом | Причина | Решение |
|---|---|---|
| Новый чат говорит «ничего не помню» | Default branch ≠ `main` | GitHub → Settings → General → Default branch → `main` |
| `MEMORY.md` не обновляется сам | Claude не запомнил правило проактивности | «Прочитай `CLAUDE.md` полностью и следуй разделу про MEMORY.md» |
| Ошибка `git checkout main` | На рабочей ветке незакоммиченные изменения | Сначала `git add . && git commit -m "wip"`, потом `checkout main` |
| Коммиты в `MEMORY.md` идут, но новый чат не видит | Запушено в feature-ветку, не в `main` | `git log origin/main -- MEMORY.md` — проверь, что твои коммиты там |

## Локальный CLI — отдельный случай

Если ты используешь Claude Code **в терминале на своём компьютере** (команда `claude`, не через браузер):

- Домашняя папка `~/.claude/` **не стирается** между сессиями
- Можно настроить **хуки** для автоматического саммари через Stop hook
- Подход с `~/.claude/MEMORY.md` + `settings.json` работает

Но это отдельный мир. Большинство сегодня через `claude.ai/code` — для них работает только репо-based подход из этого гайда.

---

## Главные правила

1. **Память живёт в репо** на ветке `main`, а не в `~/.claude/`. В сендбоксе `~/.claude/` стирается.
2. **Default branch должен быть `main`** — иначе новые чаты клонируют другую ветку.
3. **`CLAUDE.md`** — постоянное (кто ты, правила). **`MEMORY.md`** — динамика (что было в сессиях).
4. **Обновляй `MEMORY.md` только в `main`**. Feature-ветки новым чатам не видны.
5. **Никаких секретов в git.** Токены — в `.env`.
6. **Правило проактивности** в `CLAUDE.md` важнее напоминания «обнови память» — сессия может упасть раньше, чем ты об этом вспомнишь.
