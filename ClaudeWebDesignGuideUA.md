🎓 ГАЙД №30: Чому Claude Code робить «полотно» замість сайту — і як це чиниться за 15 хвилин

Найчастіша претензія до Claude Code у вебі: «він просто пише полотно». Довга однотипна простиня, все однієї ширини, три однакові картки під кожним заголовком, фіолетовий градієнт у шапці.

Це **не стеля моделі**. Це дефолт: коли в задачі немає арт-дирекшну, а в проєкті немає дизайн-правил — агент видає найбезпечніше середнє по інтернету. Нижче — що поставити, що дописати в проєкт і як формулювати задачу, щоб дизайн зʼявився з першої ітерації.

---

## Діагноз: чотири причини «полотна»

| Причина | Що відбувається |
|---|---|
| **Немає арт-дирекшну в задачі** | «Зроби лендінг про Х» — задача без жодного візуального обмеження. Модель бере статистичне середнє: центрований герой, три картки, відгуки, футер |
| **Немає правил у проєкті** | Якщо в `CLAUDE.md` нічого не сказано про дизайн, кожна нова сесія починає з нуля і заново винаходить відступи. Звідси різнобій між секціями |
| **Не підняті дизайн-скіли** | Скіли — це процедурне знання: шкали, сітки, типографіка, доступність. Без них агент верстає «по памʼяті», а памʼять у нього усереднена |
| **Одна ітерація замість пʼяти** | Дизайн не робиться за один прохід ні людиною, ні агентом. Один запит → один файл на 900 рядків → далі тільки косметика |

**Перевірка за 10 секунд.** Відкрий останній сайт, який зробив агент, і порахуй: скільки там *різних ширин контенту*? Якщо одна на всю сторінку — це і є полотно. Жива сторінка змінює ритм: широкий герой → вузький текст на 65 символів → повноекранний блок → сітка → знову вузький.

---

## Крок 1. Поставити дизайн-скіли

Виконати в корені проєкту. Ставляться в `./.claude/skills/`, Claude Code підхоплює одразу, перезапуск не потрібен.

```bash
# дизайн і фронтенд від Anthropic: frontend-design, canvas-design,
# theme-factory, brand-guidelines, webapp-testing
npx --yes skills add anthropics/skills -y -a claude-code -s '*'

# гайдлайни вебдизайну і React-практики від Vercel
npx --yes skills add vercel-labs/agent-skills -y -a claude-code -s '*'

# ui-ux-pro-max — найщільніший по UI з безкоштовних
npx --yes skills add nextlevelbuilder/ui-ux-pro-max-skill -y -a claude-code -s '*'

# перевірка
ls .claude/skills/ | wc -l
```

Що з цього найважливіше:

- **frontend-design** — не дає скотитися в «дефолтну AI-естетику», тримає планку продакшн-якості
- **ui-ux-pro-max** — компоненти, стани, відступи, патерни інтерфейсу
- **web-design-guidelines** — чек-лист правильної верстки: типографіка, контраст, фокус, адаптив
- **theme-factory** — цілісна тема: палітра, токени, темна і світла версії
- **webapp-testing** — ключове: агент запускає браузер і **дивиться на свою роботу скріншотом**

⚠️ Скіли **не спрацьовують самі від слова «сайт»** — вони підключаються за описом задачі. Тому однієї установки мало: потрібен блок правил із кроку 2, який прямо приписує їх піднімати.

## Крок 2. Дописати правила в CLAUDE.md

Це дає 80% результату. Файл `CLAUDE.md` у корені проєкту агент читає перед кожною задачею — правила діють у всіх майбутніх сесіях. Копіюй цілком:

```markdown
## Дизайн — обовʼязкові правила проєкту

Перед будь-якою версткою піднімай скіли: frontend-design,
ui-ux-pro-max, web-design-guidelines. Не верстай «на дефолтах».

1. Спочатку система, потім сторінка. Першим файлом — токени:
   палітра, шкала типографіки, шкала відступів, радіуси, тіні.
   Усе через CSS-змінні. У розмітці не повинно зʼявитися
   жодного числа повз шкалу.
2. Відступи — тільки шкала 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96.
   Ніяких 13px, 27px, 42px.
3. Типографіка — максимум 2 гарнітури. Заголовки: clamp(),
   line-height 1.02-1.15, трекінг -0.02em. Текст: 16-18px,
   line-height 1.55-1.65, довжина рядка 60-75 символів
   (max-width: 68ch). Між заголовком і текстом різниця
   мінімум у 2 щаблі шкали.
4. Ритм. Секції чергують ширину і щільність: широкий герой →
   вузький текст → повноекранний блок → сітка. Одна ширина
   на всю сторінку = полотно, це брак.
5. Один акцентний колір. Решта — фон, чорнило і 2-3 відтінки
   сірого. Акцент займає менше 10% екрана.
6. Ієрархія. На першому екрані рівно одна головна думка і одна
   цільова дія. Усе інше — тихіше за контрастом і розміром.
7. Ніяких emoji в інтерфейсі замість іконок. Іконки — SVG,
   один набір, одна товщина лінії.
8. Анімація — тільки поява при скролі і hover-стани,
   180-320 мс, одна крива на проєкт. Обовʼязковий
   prefers-reduced-motion.
9. Контент справжній. Ніяких «Lorem ipsum», «Наша команда
   професіоналів» і вигаданих логотипів клієнтів. Немає
   тексту — спитай у мене, не вигадуй.
10. Перевірка перед здачею. Відкрий сторінку в браузері,
    зніми скріншот на 1440 і 390 px, подивись на нього і сам
    перелічи 5 слабких місць. Потім виправ їх.

Заборонено: фіолетово-сині градієнти, скло на всіх блоках,
три однакові картки під кожним заголовком, усе по центру,
тіні за замовчуванням, дефолтний Tailwind-вигляд без токенів.
```

Орієнтири, до яких зводиться весь блок: **2** гарнітури, **1** акцентний колір, сітка відступів **8px**, довжина рядка до **68ch**.

## Крок 3. Як ставити задачу

Різниця між «полотном» і дизайном найчастіше в чотирьох рядках брифу.

❌ **Так виходить полотно:** «Зроби лендінг для студії ремонту». Нуль обмежень → агент бере середнє. Претензій йому не предʼявиш: він зробив рівно те, що попросили.

✅ **Так виходить дизайн** — бриф + референси + три напрямки:

```
Робимо лендінг. Спочатку задай мені уточнювальні питання, потім працюй.

ПРОДУКТ: <що це, чим відрізняється від конкурентів>
АУДИТОРІЯ: <хто, з якого пристрою прийде, що вирішує>
ОДНА ДІЯ: <що людина має зробити на сторінці>
НАСТРІЙ: <3 прикметники: напр. строгий, дорогий, технологічний>
РЕФЕРЕНСИ: <2-3 посилання> — подобається <типографіка / ритм /
   робота з фото / великі цифри>. Не копіювати, взяти принцип.
БРЕНД: <кольори, шрифти, лого — або «немає, запропонуй»>
СТЕК: <чистий HTML+CSS / Next.js + Tailwind / …>

ЗДАЧА ПО ЕТАПАХ:
1. Спочатку три РІЗНІ напрямки тільки для першого екрана,
   трьома окремими файлами. Різні за типографікою і композицією,
   а не за кольором кнопки. Я оберу один.
2. Потім токени і один еталонний блок.
3. Потім решта секцій по одній, зі скріншотом після кожної.

Не пиши всю сторінку одним файлом за один захід.
```

**Одна фраза, яка працює найкраще.** Коли результат уже є:

> «Оціни свою роботу як арт-директор за 10-бальною шкалою. Назви 5 конкретних проблем композиції і типографіки. Потім виправ їх.»

Модель критикує себе помітно суворіше, ніж проєктує з нуля — цим і користуємось.

## Порядок роботи: не «зроби сайт»

1. **Бриф і питання.** `/brainstorming` або просто «спочатку задай мені питання». Пʼять хвилин розмови економлять три переробки
2. **Три напрямки першого екрана.** Три файли, три різні композиції. Обираєш одну — далі вся сторінка живе за її законами
3. **Токени і еталонний блок.** `tokens.css` плюс одна секція, доведена до ідеалу. Це зразок, за яким агент збере решту
4. **Секції по одній.** Кожна — окрема задача зі скріншотом і правками. Ніяких «а тепер зроби решту 8 секцій»
5. **Фінал.** Адаптив на 390 px, доступність (контраст, фокус, reduced-motion), швидкість — і тільки потім деплой

## Дай агенту очі

Агент пише код наосліп: він не бачить, що вийшло, поки йому не покажеш. Два способи показати.

**Спосіб 1 — скріншот руками.** Зроби скріншот сторінки і перетягни прямо в чат: «ось що вийшло, розбери як арт-директор і почини». Працює завжди, ставити нічого не треба.

**Спосіб 2 — агент дивиться сам.** Скіл `webapp-testing` плюс Playwright:

```bash
npm i -D playwright && npx playwright install chromium
```

Далі в чаті:

```
Запусти сторінку локально, зніми скріншоти на 1440 і 390 px,
подивись на них і перелічи, що виглядає слабко.
Виправ і покажи «до / після».
```

## Симптом → чим лікувати

| Симптом | Лікування |
|---|---|
| Усе однієї ширини, нескінченна стрічка | Задати ритм: герой на всю ширину → текст на 65 символів → повноекранний блок → сітка. Прямо так і написати в задачі |
| Заголовок майже як текст | Немає типографічної шкали. Різниця між h1 і абзацом — мінімум **утричі**, плюс вага і трекінг |
| Три однакові картки всюди | Дефолтний патерн. Заборонити в `CLAUDE.md` і просити **різні типи блоків**: список з цифрами, велика цитата, порівняння, таблиця |
| Строкато, «очі розбігаються» | Більше одного акценту. Залишити один колір, решта — відтінки сірого |
| Порожньо і «дешево» | Зазвичай навпаки — бракує контрасту розмірів і повітря в потрібних місцях: 96-128 px між секціями, 8-12 px усередині картки |
| На телефоні розʼїжджається | Верстали desktop-first. Просити перевіряти **390 px після кожної секції**, а не в кінці |
| Красиво, але не продає | Це вже не дизайн, а тексти і структура. Скіли `copywriting` і `page-cro` з маркетингового пакета |

## Чого не робити: впізнаваний AI-вигляд

- **Фіолетово-синій градієнт** у герої — головна прикмета «зроблено нейронкою за 30 секунд»
- **Скло (glassmorphism) на всіх блоках одразу.** Ефект працює, коли він один на сторінці
- **Emoji замість іконок** у списках переваг
- **Вигадані логотипи клієнтів** і «нам довіряють 10 000 компаній» без підстав. Крім шкоди для довіри, це ще й юридичний ризик
- **Усе по центру.** Центрування — прийом для акценту, а не режим за замовчуванням
- **Тіні за замовчуванням** на кожній картці. Або тіні як система (2-3 рівні), або межі
- **Правки по одній дрібниці в нескінченному чаті.** Дешевше переформулювати задачу і переробити секцію цілком
